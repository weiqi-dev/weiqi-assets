# JSON 查询与提取（llm-tool）

`llm-tool` 扩展点的通用数据提取工件。装进宿主、人工启用后，对话里的模型就能通过
`llm_tool_call` 把一段 JSON 按语法选取、筛选、搜索、探结构；**调用时零网络**
（源码已在本地工件里），每次调用仍在一次性 QuickJS Worker 里执行，库源码不进
主线程 JS 环境、不进模型上下文。

定位类似命令行里的 `grep` 那一层：输入是 JSON，输出是 JSON，操作是确定性的纯函数
（不读时钟、不联网、不产生随机数）。这样模型就不必通读一大段 JSON 再凭记忆复述
—— 尤其当 `web_fetch` 观察文本被宿主的字符上限截断时，至少能把「已经拿到的部分」
精确取出来，不会把看不到的部分补出来。

## 三个方法

| 方法 | 作用 | 类比 |
|---|---|---|
| `query` | 路径选取 + 条件筛选 + 字段投影 + 限量/计数 | 路径选择 + `where` |
| `grep` | 遍历全部标量叶子，用正则匹配其字符串形式，回带路径的命中 | `grep -n` / `grep -c` |
| `outline` | 描述某路径命中节点的一层结构，不展开子层 | 探结构，先知道 JSON 长什么样 |

三个方法都接受 `json`（已解析的值）或 `text`（JSON 字符串）**二选一**；
`text` 由本库严格 `JSON.parse`，解析失败明确抛错，不猜测、不宽松修复。
不传 `json` 也不传 `text`、或两者都传，一律报错。

### 输入与输出

```
llm_tool_call({
  libId: "<system 里「可用能力库」列出的 id>",
  method: "query",
  args: [{ json: <值>, select: "...", where: [...], pick: [...], limit: n, count: bool, paths: bool }]
})
```

`query` / `grep` 返回：

```json
{
  "ok": true,
  "matched": 3,
  "returned": 3,
  "truncated": false,
  "items": [ { "path": "$.Years.2027[0].Name", "value": "春节" }, ... ]
}
```

- `matched` 是筛选后命中总数，`returned` 是实际回传条数，`truncated` 标明是否因
  `limit` 被截短。**不设默认 limit**：不传就全量返回，输出体积由宿主
  `DEFAULT_PLUGIN_LIMITS.maxOutputBytes` 兜底，资源侧不复制配额数值。
- `paths` 默认 `true`，`items` 每项 `{path, value}`；`paths:false` 时每项直接是值，
  便于少占字符。`count:true` 时只回 `{ok, matched}`，连 `items` 都不回。
- `outline` 返回 `{ok, matched, nodes[]}`，每个 node 带 `path` 与 `type`：
  对象给 `keys`，数组给 `length`，标量给 `value`。不受 `count` / `limit` 影响。

## 路径表达式（本工件自定义）

语法是本项目自写的，没复制任何第三方实现。借鉴 JSON Pointer（RFC 6901）「按段定位」
的思想，但转义、通配、递归、负下标的语义全部在下面逐条定义：

| 写法 | 语义 | 来源 / 理由 |
|---|---|---|
| `$` | 根节点；可省略 | 常见根符号，仅作起点标记 |
| `.name` | 对象键；路径开头可直接写 `name` | RFC 6901 按段定位的思想 |
| `["name"]` | 含特殊字符的键；转义按 JSON 字符串规则 | 让键名含 `.` / `[` 时仍可表达，输出路径也用这个形式，可原样回贴 |
| `[n]` | 数组下标，从 0 起 | ECMAScript 数组索引定义 |
| `[-n]` | 倒数第 n 个（`-1` 是最后一个） | 常见「倒数第 n 个」语义，n 由调用方给出 |
| `[*]` / `[]` / `.*` | 展开当前层全部子节点，顺序为原顺序 | 对标 shell 通配符，三种写法等价 |
| `..name` | **当前节点自身及所有后代**中含该键者 | 对标 XPath `//` 的直觉；语义在此明确定义，不沿用别处边界约定 |

段可连续书写，例：

```
Years.2027[*].Name          → 2027 年每个节日的 Name
Years.2027[-1].StartDate    → 最后一个节日的起始日
..CompDays[*]               → 任意层级下所有 CompDays 数组的元素
["a.b"].q                   → 键名含点时的写法
```

实现用**显式队列 + 广度优先**，不做函数递归（宿主栈上限 512KB，深结构递归会爆栈）。
`..name` 的结果顺序是广度优先顺序，**确定但不等于文档出现顺序** —— 需要文档顺序时
请改用明确的 `select` 路径。路径解析失败会抛错（如 `..` 后无键名、下标非整数、
引号未闭合），不会静默返回空。

输出里的 `path` 用同一套语法书写，可以直接复制回 `select` / `path` 复用。

## `where` 条件（仅 `query`）

`where` 是条件数组，**项间为 AND**；每项 `{ path?, op, value?, flags? }`。
`path` 省略或 `$` 表示「当前候选节点自身」，其余按上面的路径语法解析。

| op | 语义 | 边界 |
|---|---|---|
| `exists` | 该路径至少命中一个节点 | 不需要 `value` |
| `eq` / `ne` | 深度相等 / 不等 | 纯 JSON 值深度比较，不做隐式类型转换 |
| `in` | 命中值在 `value` 数组里 | `value` 必须是数组 |
| `contains` | 字符串含子串 / 数组含元素 / 对象含该键 | 三类各自明确定义，不混用 |
| `startsWith` / `endsWith` | 字符串前缀 / 后缀 | 两边都必须是字符串，否则判不满足 |
| `gt` / `gte` / `lt` / `lte` | 数值或字典序比较 | **类型不同或不是数值/字符串一律判不满足**，不隐式转换 |
| `match` | 正则匹配标量的字符串形式 | `value` 是正则字符串，`flags` 可选（不含 `g`/`y`） |

同一路径命中多个节点时，只要**任一**命中满足条件即算通过（`some` 语义，
对标 grep「有一行匹配就算命中」）。`eq`/`ne` 等对 `null`、对象、数组都做结构比较。

## `grep` 的边界

- 只遍历**标量叶子**（字符串 / 数值 / 布尔 / null）并匹配 `String(value)`；
  对象与数组本身不参与匹配，避免把容器结构当成文本。
- `pattern` 是正则字符串，语法受 QuickJS 正则实现限制（不支持 lookbehind 等新特性）。
- `flags` 禁止 `g` / `y`：`RegExp.test` 会记住 `lastIndex`，同一正则在不同节点上
  结果会依赖遍历顺序而变得不确定。这是确定性要求，不是风格偏好。
- 不支持 `where` / `pick`；要缩范围先用 `query` 的 `select`，或先用 `outline` 探结构。

## 数值与常数的来源（这条最要紧）

本工件**没有任何经验阈值、拟合系数、扫出来的门控**：

| 出现处 | 来源 | 性质 |
|---|---|---|
| 路径分段、特殊键引号 | JSON Pointer RFC 6901 的「按段定位」思想 + ECMAScript 字符串规则 | 公开标准 / 语言定义 |
| 数组下标从 0、负下标倒数第 n | ECMAScript 数组定义 + 常见倒数语义 | 语言定义 / 语义约定 |
| `..name` 含自身与全部后代 | 本文件明确定义（对标 XPath `//` 直觉） | 明说的语义，可争议可改 |
| 广度优先、显式队列 | 宿主 `DEFAULT_PLUGIN_LIMITS.maxStackBytes` 的栈约束 | 宿主既有约束，非本库自设 |
| 严格相等 / 数值比较 / 子串 | ECMAScript 标准语义 | 语言定义 |
| 不设默认 `limit` / 深度 / 条数 | 业务决定「取多少」由调用方显式给出 | 明说的业务约束 |
| 输出体积、执行时间、代码体积 | 宿主 `DEFAULT_PLUGIN_LIMITS` | 宿主配额，资源侧不复制数值 |

**本文件的路径解析、遍历、条件匹配、输出组装全部自写**，不含任何第三方库的
实现代码（没有引入 jq、JSONPath、lodash 等）。语法借鉴的是公开标准与命令行直觉，
不是复制实现。

## 能解决什么、不能解决什么

配合月历这类配方时，它能把 `web_fetch` 取回的节假日 JSON 按 `select` 精确取出
「某一年、某个月」的片段，避免模型通读被截断的全量文本后猜数据。但它**不能**
突破宿主 `ToolLoop` 的观察文本裁剪 —— 观察本身只到了前 2000 字符，后面就不在
输入里了。要根治那个问题得改宿主（分批取数 / 给观察文本开白名单），不是这个库
能兜住的。这一点如实说明，不夸大能力。

它也不是数据库：不做排序、不做聚合（求和/分组）、不做跨文档 join。
需要这些时请另写工件，或在调用方按 `items` 自行处理。

## 安装形状

与 `lunar` 工件逐字相同：宿主取 `plugin.json` → 按 `code` 取源码 → 静态预检 +
沙箱逐条跑 `smoke[]` 并比对 `expect` → 写进工件存储，**默认停用**。
用户在「插件」面板启用后，chat / skill-dev 角色才会看到并调用它。

`smoke[]` 覆盖三个方法、路径通配 / 负下标 / 递归下降 / `text` 解析 / `where` /
`pick` / `count` / `paths` / `grep` / `outline`，全部是确定性断言。
